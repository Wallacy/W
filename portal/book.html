Capítulo 1

Promessa e estado

Prazer para humanos. Clareza para máquinas. W quer unir aplicação legível, sistemas nativos, concorrência estruturada e controle explícito de ABI. Custos ou efeitos importantes devem aparecer no contrato ou no ponto de uso.

Candidato experimental

Existe uma baseline integrada, uma gramática Tree-sitter e um ensaio visual. Ainda não existem compilador, type checker, runtime ou SDK W.

Uma decisão pode estar como Direção, Forma vigente, Alternativa, Pesquisa ou Rejeitado por enquanto. O líder permite testar um sistema coerente; ele não congela a linguagem.

Capítulo 2

Source, módulos e entradas

Um módulo é namespace e unidade lógica no grafo. Ele não possui thread, heap, singleton ou inicialização implícita. O manifest reúne vários arquivos e impede cycles de implementação.

import std.http
import { Order } from restaurant.domain
import std.tensor as tensor

export type OrderId = u64

entry LastLight {
  process.main = run
  process.stdinLine = readCommand
  http.fetch = fetch
}

Declarações são privadas por default. package abre o package e export cria a interface. Import não executa código nem concede capabilities. Um entry liga funções comuns a slots tipados do host.

Forma curta

entry { print("Hello, W") } só existe quando o product possui um único slot default. Não há busca mágica por uma função chamada main.

Capítulo 3

Tipos, funções, ausência e falha

export type GuestId = u64
export type GuestCount = u16 where (value in 1...4096)
export alias RawCount = u16

fn reserve(for guest: GuestId, seats: GuestCount): Reservation throws BookingError {
  guard seats > 0 else throw .emptyParty
  return try ledger.reserve(for: guest, seats: seats)
}

type cria identidade nominal sem storage extra. alias cria um sinônimo. where refina valores. Input dinâmico usa construção fallible; um literal inválido pode falhar no compile time.

T? contém .some(T) ou .none. Errors recuperáveis usam throws E, try e cases tipados. Conversão implícita exige uma rota única, total e sem perda.

let mapper = capture(take table, ref metrics) (item) => {
  return table.lookup(item) ?? metrics.fallback
}

Closures inferem captures locais. Uma closure que escapa ou cruza um executor torna transferências e borrows explícitos.

Capítulo 4

Memória, layout e property behaviors

O caminho comum usa owner único, move, borrows locais inferidos e destruição determinística. ref empresta leitura, inout empresta mutação, take transfere ownership e copy pede uma cópia deliberada. shared T torna compartilhamento explícito.

export service Kitchen as KitchenApi {
  var Lazy calibration = loadCalibration()
  var atomic completed: u64 = 0

  mut async fn prepare(order: take Order): Dish throws KitchenError {
    // ...
  }
}

var Behavior name compõe um contrato de storage/acesso sem um sistema universal de annotations. Behaviors não podem esconder I/O, suspensão ou falha não declarada.

Representação não é semântica

Layout W comum é opaco. ABI C, schema, packed/aligned e storage inline usam fronteiras explícitas. Pointer tagging, SSO e mimalloc são otimizações com fallback, não promessas no source.

Capítulo 5

Concorrência, paralelismo e services

async on .network let stock = pantry.reserve(order.course)
async on .network let telemetry = ovens.telemetry()
spawn on .compute let plan = oracle.plan(order)

let (stock, telemetry, plan) = try await (stock, telemetry, plan)
defer async { await stock.release() }

async let cria trabalho suspensível concorrente. spawn let pede capacidade paralela. on seleciona uma preferência de execução, não uma thread física. Todo filho pertence a um scope; falha e cancelamento fecham a árvore.

Um service é uma instância lógica endereçável com turn serial fechado, mailbox bounded e lifecycle observável. Uma ServiceRef<P> sempre exige await, local ou remota. O runtime pode co-localizar e fundir calls pela regra as-if.

Fine-grained não significa fragmentação física

Identity, state, quota e trace podem ser finos. Processos, threads, connections e libraries continuam decisões de packing do runtime e do deployment.

Capítulo 6

Ranges, unidades, matrizes e ML

let gravity = 9.80665<m/s^2>
let setpoint = 180<degC>
let memory = 64<KiB>

dimension Applause
unit clap: Applause
unit ovation = 1_000<clap>

<unit> é o líder experimental. Ele preserva [] para collections, indexação, slices e shapes. Units lineares, afins e logarítmicas mantêm contratos diferentes. Currency e calendário não fingem ser unidades físicas.

let observations: Tensor<f32, shape: [2, 3]> = [
  [1.0, 0.0, 0.5],
  [0.2, 0.8, 0.0],
]

let logits = observations @ weights
let probabilities = logits.softmax(axis: 1)

Arrays aninhados são o literal canônico. @ expressa contração matricial. Shapes estáticos podem falhar no type checker; shapes dinâmicos falham com error. Broadcast não escalar e transfer de device ficam explícitos.

Capítulo 7

C, unsafe, frontend e compilação

foreign c from "last_light_probe.h" {
  type ll_probe
  fn ll_probe_read(probe: c.ptr<ll_probe>, sample: c.ptr<ll_sample>): c.int
}

let status = unsafe { ll_probe_read(handle, inout raw) }

C é uma fronteira de ABI. Wrappers W restauram ownership, nullability, cleanup e typed errors. fn<C> é o primeiro experimento de ilha de linguagem inline; outros frontends só entram com ABI, exceptions, runtime e debug bem definidos.

W source → CST/AST → HIR tipada → dialeto W no MLIR
         → lowerings de ownership, effects, tasks e layout
         → LLVM dialect → LLVM IR → código nativo

Tree-sitter serve edição e pode acelerar o bootstrap. Ele não faz type checking nem lowering. O seed usa C11, CMake e Ninja. W deve se tornar self-hosted cedo, mantendo o seed como caminho de auditoria.

Capítulo 8

SDK, build, packages e distribuição

A standard library usa módulos concretos, como std.io, std.net, std.math e std.tensor. Todos seguem o mesmo contrato de suporte; capabilities, target availability e reachability determinam o que entra no produto.

w build --locked --target x86_64-windows
w explain dependency kitchen
w explain resource restaurant.http
w verify artifact last-light.exe

Manifest é data-only. Lock fixa identity, source, artifacts, features, toolchain e digest. Builds herméticos normalizam inputs e produzem um registro de auditoria. O artefato inicial é source-first; static libraries são preferidas quando compatíveis.

Evidence sem selo mágico

Integridade, reprodução, provenance, análise e confiança do mantenedor são eixos separados. Uma hash prova identidade de bytes. Uma assinatura não prova segurança. Platform signing continua independente.

Capítulo 9

Restaurante Última Luz

O ensaio acompanha uma comanda desde CLI ou HTTP até parsing, service, estoque, forno, planejamento tensorial, sonda C, cobrança e resposta. O cenário usa humor cósmico original para pressionar casos comuns e extremos sem depender de uma API fictícia simples.

LastLight entry
  → Comanda de Íon
  → Salão Prisma
  → Cozinha de Maré Fria
  → Brigada do Cometa Manso
  → Oráculo de Mesas
  → Sonda de Aroma
  → Conta da Aurora Tardia
  → resposta HTTP/TUI

Uma falha injetada em cada seta não pode deixar task, lease, buffer, mailbox item ou pagamento sem owner e estado observável.

Capítulo 10

Como revisar sem perder alternativas

A seção 28 de DESIGN.md possui 96 decisões. Cada linha mostra o líder atual e as alternativas preservadas. Uma revisão pode citar somente os IDs que deseja mudar.

W-014  refinement   T where (predicate)   | T(where:); T<where(...)>
W-039  domain       spawn on .compute     | spawn<.compute>; descriptor
W-051  unit         9.81<m/s^2>           | []; {}; whitespace SI
W-064  matrix       nested arrays         | semicolon; constructor
W-073  parser       recursive/Pratt       | generated; Tree-sitter

O teste mede correção antes de preferência. Cada comparação usa o mesmo programa, perguntas de leitura, uma correção de bug e uma alteração. O projeto registra erro, tempo, hesitação e explicação. Pessoas e modelos usam o mesmo oracle, mas resultados separados.

  1. Leia a superfície como um programa completo.
  2. Use o restaurante para verificar como as peças se encaixam.
  3. Compare somente os casos que causam dúvida real.
  4. Responda por ID W; a alternativa continua preservada.
