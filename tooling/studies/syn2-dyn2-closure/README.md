# SYN2/DYN2 — typed generation and versioned behavior closure

SYN2/DYN2 is a small closure study. It reuses the SYN1, DYN1, and HRD0
artifacts. It does not copy their 155 cases and it does not claim a W compiler,
runtime, provider, or release implementation.

## Closed design contract

SYN2 promotes one narrow C route. A W0 hermetic and bounded transform may emit
a content-addressed set of `.w` source units with action result, provenance,
and source-map receipts. The build publishes the action result and CAS object
separately from the candidate interface and from any compiler cache. Every
generated unit is reopened as a normal source unit before interface freeze and
passes parse, name, type, ownership, effect, and `ConstIR` phases. A target-
neutral semantic identity is shared by projections. A target-specific receipt
adds the target registry digest and exact `WAbi` facts. Recipe, artifact,
interface, source-map, documentation, and package identities remain separate.

The contract does not add syntax. It does not splice HIR, inject declarations
into the current module, use ambient authority, or accept a typed recipe/IR
that duplicates the frontend. Eval, exec, macros, decorators, metaclasses, and
active-module mutation remain rejected mechanisms.

Action success may publish an action result before parse or receipt checking
finishes. A later parse, receipt, or map fault keeps that result but publishes
no interface or compiler cache. Error, cancellation, quota, or OOM before the
result discards staging with the reserved host bookkeeping sequence cleanup,
drain, and discard exactly once. Panic crosses the fault boundary: it does not
promise user `defer` or `deinit`; the host releases resources registered with
that boundary, as specified by [DESIGN §11.6](../../../DESIGN.md#116-cleanup).
Success performs no invented cleanup. Source maps use current byte/UTF-8 boundaries,
permit many generated spans to one source span, and never invent a fix for a
generated-only span.

DYN2 closes the A/B/dev-only route. A REPL snapshot is immutable and export is
bounded. A typed service/plugin generation uses exact semantic, schema, ABI,
runtime-closure, capability, effect, artifact, and package identities. Local
and split projections must have equal logical outcomes; physical traces may
differ. A development runner reopens normal W units and uses
`prepare -> validate -> preflight -> ready -> switch`; it adds no syntax,
source/package profile, or release dynamic mode.

The study calls its tooling/artifact schema `GenerationReference`. It is a
bounded, read-only identity record with exactly these eight fields. It adds no
source spelling and no public nominal W API:

`generationId`, `artifactDigest`, `recipeDigest`, `semanticInterfaceKey`,
`schemaDigest`, `targetReceipt`, `resolveReceipt`, and `migrationReceipt`.

`targetReceipt` may contain WAbi/runtime-closure facts for an exact target
route, but the GenerationReference does not add optional fields. It is not
§23.1.6 `PersistentRef<P>`, carries no capability or authority, and cannot
convert to `ServiceRef`. The resolve and
migration receipts only re-resolve or rebind identity and schema. They never
migrate live state. Extra, missing, duplicate, or repeated fields are rejected.
The record never carries heap, task, loan, frame, capability, `ServiceRef`,
callback, or provider-handle state. Export/import reopens, parses, checks, and
resolves receipts; it never restores live state.
Eval/exec, monkey patching, active-frame or debugger writes, ambient lookup,
native dynamic libraries as sandboxes, live `dlclose` callbacks, and production
arbitrary hot reload remain rejected.

Publication is atomic. Before switch, failure preserves the old generation;
provider rollback is valid only with an explicit pre-publication receipt.
After switch, old admission closes. Logical cleanup is cancel, drain,
unregister, in-flight drain, destroy, and release. `unpin` is added only when a
pin/FFI fact exists. `unmap` is added only for a mapped process/Wasm/component
after views and callbacks drain; an exact-WAbi native mapping remains retained
until the runtime island is safely closed. A post-switch drain fault is
`degraded`, never rollback.
Stale completion, capability, or schema events are rejected. Quotas bound
source, generated bytes, CAS, receipts, maps, history, effects, and cleanup.

## Evidence boundary

The corpus is a host design oracle. It reuses the source references, target
registry, action/result cases, receipts, independent local/split reducers, and
mutation rejects from SYN1, DYN1, and HRD0. It proves classification boundaries
and derived rejection outcomes only. Compiler semantic phases, CAS/build
implementation, target compiler/provider, runtime/provider, OOM/fault
receipts, isolation, stress, FFI execution, and human/model studies remain
implementation-evidence gaps. A host parser or registry fixture is not a
compiler or provider.

## Stop condition

Stop the closure if any independent reducer accepts caller-owned status,
route, expected result, or failure selector; if action and interface/cache
identities collapse; if a generated unit is not reopened; if an identity,
authority, capability, effect, ABI, source-map, package, quota, cleanup, or
fault receipt is stale, forged, hidden, or unbounded; if a local/split logical
result diverges; if persistent data contains live state; or if a rejected D
mechanism is required. Reopen only for a bounded Last Light problem with a
fresh case, source digest, independent oracle, and reviewed design decision.
